# T4 추가 측정과 수용 조건 대조

2026-09-28. 기존 후향 관측에서 빠졌던 단계 시간을 새 실제 작업 3개에서 기록했다.
T4의 필수 측정값은 확보했다. 최초 전체 검증은 600초 suite 제한에 걸렸다.
[테스트 자원 관리 회귀](2026-09-28-test-fixture-resource-ownership.md)를 수정했고,
최종 통합 판정은 `.test-runs/t4-completion/final.json`의 결과를 따른다. 아래 표본은 개발 도구 보완 작업이며,
제품/UI 작업의 소요 시간이나 독립 SDD 에이전트 3명의 성능을 대표하지 않는다.
기존 과제의 미측정 시간을 소급해 채우거나 수용 조건을 삭제하지 않았다.

## 측정 방법

단일 controller가 작업 전에 `implementation`을 시작하고, 검증 시 `test`,
코드와 실행 증거 검토 시 `review`로 전환했다. monotonic clock으로 각 구간을 계산했다.
각 단계 전환의 UTC·단조 시각·부팅 세션 ID를 [원본 journal](2026-09-28-superpowers-t4-phases.json)에 보존한다.
테스트 실행과 결과 확인까지는 test 단계다. 외부 승인·에이전트·자원 대기는 발생하지 않아
세 과제의 `observed_absent_phases`에 waiting을 명시했다. 기록 누락을 0으로 대체하지 않는다.
단계 전환 사이의 도구 호출 간격, 사전 조사, 측정 준비, 최종 보고서 작성은 이 과제 시간에서 제외한다.

사전 조사에서 기존 기록기가 macOS의 변동 가능한 `psutil.boot_time()`을 부팅 신원으로
비교해 종료 기록을 거부하는 문제를 재현했다. `kern.bootsessionuuid`로 수정하고 CLI 검증을
추가했다. 완료한 구간 사이의 역순 시각·재부팅·NaN/무한대도 거부한다.
이 사전 작업은 P4-clock이며, 중단된 이전 journal과 함께 `.test-runs/t4-completion/`에 남겼다.
**P4-clock의 짧은 패치 적용 구간과 불완전한 이전 기록은 대표 3개에 포함하지 않았다.**

과거 boot ID 없는 journal은 기존 boot_time 계약으로 읽을 수 있다. 새 형식과 섞어 재개하면
신원 확인 실패로 거부하므로 새 journal을 시작한다. 기존 기록을 덮어써 부팅 신원을 추정하지 않는다.

## 실제 과제 3개

| 과제 | 구현(초) | 테스트 단계(초) | 리뷰(초) | 외부 대기(초) | worker(초) | 대상 검증 |
|---|---:|---:|---:|---:|---:|---|
| P5 보고서에 과제별 단계 시간 연결 | 61.35 | 13.17 | 8.21 | 0 | 0.56 | 17 passed |
| P6 usage 신원 보존·중복 집계 수정 | 65.12 | 26.77 | 12.00 | 0 | 0.52 | 19 passed |
| P7 측정 누락의 자동 완료 판정 차단 | 69.81 | 19.20 | 16.55 | 0 | 0.69 | 20 passed |

테스트 단계에는 실행 명령 준비·실제 테스트·도구 결과 확인이 포함된다. 실행기 자체 wall은
각각 2.13/1.76/1.99초이며 worker는 pytest setup/call/teardown report 합이다.
이 세 종류의 시간을 더하지 않는다. 측정은 순차 진행했고 각 대상 run은 한 과제에만 연결했다.
리뷰는 같은 controller의 별도 단계에서 수행했으며 독립 리뷰어 검증이라고 표시하지 않는다.
각 과제는 구현 1회·리뷰 1회이고, 리뷰 후 수정 라운드·Minor만의 수정 라운드·관측 flaky·
뒤늦게 발견한 회귀·범위 밖 자동 편입은 모두 0회다. 발견된 부팅 시각 문제는 위 사전 조사에 별도 기록했다.

과제별 수정과 검증 범위:

- P5: journal의 실제 값이 과제 보고서의 null을 대체한다. 누락·미종료 단계는 unknown으로 유지하고,
  명시적 부재와 실제 기록이 충돌하면 거부한다. 실제 report CLI 연결도 검사했다.
- P6: 동일 응답의 후속 usage는 토큰 수만 갱신하고 최초 모델·effort·시각은 보존한다.
  해시한 요청 ID로 겹치는 prefix를 중복 집계하지 않는다. 신원이 없는 겹친 구형 자료는 재수집을 요구한다.
  잘못된 cutoff는 파일을 읽기 전에 거부한다.
- P7: 과제 3개, 고유 과제 ID, 4단계 시간, usage, worker 시간, run 연결, 수정·품질 관측값이
  빠진 보고서는 측정 완료로 판정하지 않는다. finishing 의무 중복은 별도 집계한다.
  이 자동 검사는 측정 완결성 검사이며 제품 품질·장애 감지·성능 개선 판정을 대체하지 않는다.

## 수용 조건 대조

| 계획의 조건 | 근거와 판정 |
|---|---|
| 대표 실제 과제 3개에서 단계 시간 | 위 3개 개발 도구 작업의 사전 시작/종료 journal, 미종료 단계 없음 |
| 구현/테스트/리뷰/대기·worker 분리 | [과제 집계](2026-09-28-superpowers-t4-results.json)의 `phase_seconds`, `test_seconds`. 대기 부재는 명시적 관측 |
| 중복 실행 이유 | 코드 변경별 영향 검증. 동일 입력·환경·인자·정책의 사유 없는 중복 0회, finishing 중복 0회 |
| 장애 진단과 종료 | [기본 정책 원자료 요약](2026-09-28-superpowers-t4-diagnostic.json): 진단 요청 60.18초, 확보 60.42초, spawn부터 결과 120.68초, TIMED_OUT·정리 성공·잔류 0 |
| Minor 수정 루프·범위 확대·회귀·flaky | 위 과제 기록에 각각 0, 사전 조사에서 발견한 부팅 신원 오류는 별도 공개 |
| 캐시 전체/첫 호출·후속 호출 | 아래 usage 표와 고정 prefix 원자료. 이번 실행 주체는 controller 1개 |
| 전체 품질 확인 | `.test-runs/t4-completion/final.json`의 최종 전체 run과 입력 fingerprint를 확인 |

장애 증거는 이미 통과한 실제 60/120초 검사를 재사용했다. 원래 외부 run manifest의
supervisor SHA-256이 현재 파일과 동일한지 확인했다. 의도적 강제 종료여서 내부 결과에
`incomplete plugin session`이 남으며, 이를 정상 통과 증거로 쓰지 않는다. 진단 결과 SHA-256도 보존한다.
같은 장애 검사를 자료 수를 늘리기 위해 반복하지 않았다.

## 캐시 관측과 재현 경계

[usage 스냅샷](2026-09-28-superpowers-t4-usage.json)은 완결된 **4,010,488 bytes**와
prefix SHA-256을 보존한다. 같은 cutoff 재수집의 해시·요청별 값이 일치함을 확인했다.
원문 대화는 복사하지 않고 요청 ID도 SHA-256으로 바꿨다.

| 범위 | 요청 수 | 전체 입력 | cache read | cache creation | 미캐시 입력 | 출력 |
|---|---:|---:|---:|---:|---:|---:|
| P5 관측 창 | 4 | 220,572 | 215,680 | 0 | 4,892 | 2,296 |
| P6 관측 창 | 4 | 237,932 | 231,808 | 0 | 6,124 | 2,911 |
| P7 관측 창 | 4 | 258,425 | 253,184 | 0 | 5,241 | 2,737 |
| controller 세션 전체 prefix | 139 | 10,801,214 | 10,515,200 | 0 | 286,014 | 103,101 |
| controller 첫 기록 | 1 | 13,996 | 12,032 | 0 | 1,964 | 145 |
| controller 후속 기록 | 138 | 10,787,218 | 10,503,168 | 0 | 284,050 | 102,956 |

세션 prefix에는 이전 T0~T5 작업도 포함된다. 세션 전체를 이번 추가 작업 비용으로 해석하지 않는다.
과제 usage는 해당 시각 창에 기록된 요청 기준이며 요청 내부의 작업 비용을 인과적으로 분할한 값이 아니다.
첫 기록은 controller 세션 첫 기록이며 각 과제의 첫 호출이나 새 subagent의 첫 호출이 아니다.
모델은 gpt-6-astra, effort는 high로 관측됐다. cache creation 0은 로컬 usage 값이며 결제 금액 판정이 아니다.
변경 전의 대응 과제 표본은 없으므로 워크플로우 전체 절감률이나 장기 flaky 비율을 주장하지 않는다.

[입력 명세](2026-09-28-superpowers-t4-inputs.json)로 보고서를 재생성할 수 있다.

```sh
python scripts/workflow_metrics.py report \
  --spec docs/plans/2026-09-28-superpowers-t4-inputs.json \
  --output .test-runs/t4-completion/replay.json
```

`measurement_acceptance.complete=true`, 필수 측정 누락 0개다. 이 결과와 위 장애·품질 증거를
함께 대조한다. 최초 suite timeout과 후속 수정·최종 검증을 함께 보존하며,
최종 통합 성공은 위 final.json의 run ID와 입력 fingerprint로 확인한다.
