# 공항 주차 자동 예약 서비스

첫 화면에서 공항 서비스를 고른다. 인천공항 제2터미널 발렛파킹과 김포공항 국내선 예약주차장을 지원한다. 김포는 공식 브라우저의 결제 확인까지 준비하며, 결제와 최종 예약 결과 확인은 사용자가 직접 한다.

## 설정

Python 3.11 이상이 필요하다. 설정 파일을 표준 라이브러리 `tomllib`로 읽는다.

서비스 설정은 `config/<서비스>.toml`에 있다. 인천 T2 발렛은 `config/t2_valet.toml`이다.

| 키 | 뜻 | 규칙 |
|---|---|---|
| `request.url` | 예약 API 주소 | `http://` 또는 `https://`로 시작 |
| `request.interval_sec` | 폴링 간격 기본값(초) | 10 이상 정수 |
| `payload.car_type`, `payload.booking_type`, `payload.root` | 예약 API의 `carType`, `type`, `root` 값 | 빈 값이 아닌 문자열 |
| `payload.is_using_car_wash`, `payload.is_crew` | 예약 API의 `isUsingCarWash`, `isCrew` 값 | `true` 또는 `false` |
| `payload.customer_request`, `payload.car_wash_type` | 특별 요청, 세차 종류 | 문자열. 빈 문자열이면 보내지 않는다(null) |

설정이 잘못되면 `python3 app.py`가 `[설정 오류] config/t2_valet.toml: <키> — <이유>`를 출력하고 종료한다. 표에 없는 키도 오류다. 파일이 없거나 TOML 문법이 틀리면 그 파일의 전체 경로를 담은 오류가 나온다.

예전처럼 `.env`에 `REQUEST_URL`, `CAR_TYPE` 등을 적어 두었다면 더 이상 읽지 않는다. 값을 `config/t2_valet.toml`로 옮기고 `.env`에서 지운다. 옛 키가 남아 있으면 앱을 시작할 때 경고가 나온다.

## 실행

```bash
python3 -m pip install -r requirements.txt
python3 -m playwright install chromium
python3 app.py
```

`http://localhost:8081`을 열고 "인천공항 제2터미널 발렛파킹" 카드를 누른다. 예약 화면(`/t2-valet/`)에서 예약 정보를 입력한 뒤 **자동 예약 시작**을 누른다. 예약이 성공(HTTP 200)하면 자동 예약이 멈춘다. **1회 예약 요청**도 실제 예약을 요청하므로 성공하면 예약이 완료된다.

## 김포 예약

`http://localhost:8081/gimpo-parking/`에서 예약 정보를 입력한다. 김포 국내선 제2주차장 주차타워 2·3층을 지원하며, 할인 구분은 공식 예약 신청 화면의 일반차량·50% 할인 대상·저공해(3종) 선택지와 같다. 선택한 할인은 공식 화면에서 요금을 재계산한다. 할인 자격 조회와 PG 이후의 자동 예약 완료 판정은 아직 지원하지 않는다. 실제 사이트의 전체 흐름과 PG 결제 완료는 실예약으로 검증하지 않았다.

1. `.env`에 `RESERVATION_PASSWORD`를 영문·숫자 4~128자리로 설정한다. 서버에서 읽은 비밀번호는 읽기 전용 입력칸에 마스킹되어 표시되며, 눈 버튼으로 평문 표시를 전환할 수 있다. 표시 전용 API 응답은 캐시하지 않으며 기본 정보·작업 응답에는 포함하지 않는다. 같은 이름의 프로세스 환경변수가 있으면 우선한다.
2. **빈자리 조회**는 1회 조회 후 멈춘다. 가능하면 예약 정보 입력 → 결제 대기까지 진행을 선택할 수 있다.
3. **자동 예약 시작**은 Playwright Stealth를 적용한 Chromium 창을 한 번 열고 같은 화면에서 조회 버튼을 반복 실행한다. 최종 재조회에서 만차가 되어도 같은 창·세션으로 조회 화면에 돌아간다. 자리가 있으면 동일한 공식 세션에서 입력·중복검사·최종 잔여석 확인까지 진행한다.
4. **결제 대기 — 예약 미완료**가 표시되면 **공항 예약창 보기**를 눌러 열린 Chromium에서 직접 결제를 진행한다. 자동화는 결제 확인 버튼을 누르지 않는다.
5. 공식 예약조회에서 결과를 확인하고 **예약 결과 확인 및 종료**를 선택한다. 사용자의 확인 기록은 자동 검증된 예약 성공과 구분한다. 이 기능은 공식 예약 취소나 환불을 실행하지 않는다.

차량번호·연락처와 선택 옵션은 변경 시 이 PC의 김포 저장소에 자동 저장되고, 다음 접속 시 자동으로 채워진다. 입출차 날짜는 매번 현재 예약 가능 범위로 시작한다.

입출차는 PC의 시간대와 관계없이 서울 시간이며 10분 단위다. 입차는 보수적으로 현재부터 2시간 이후, 이용은 2시간~30일, 출차일은 오늘부터 45일 이내로 제한한다. 날짜 선택기와 직접 입력, 서버에 같은 정책을 적용한다.

김포 일반 설정은 T2와 같은 공용 TOML 로더로 `config/gimpo_parking.toml`에서 읽는다. 알 수 없는 키와 잘못된 타입은 시작 시 오류다. 수정한 설정은 앱을 재시작해야 적용된다.

| 키 | 기본값 | 범위 / 의미 |
|---|---|---|
| `request.interval_sec` | `30` | 순차 조회 간격, 30~3600초. 공항이 공지한 호출 허용 빈도는 아님 |
| `request.handoff_max_age_sec` | `120` | 결제 인계 재확인 기준, 10~600초. 주차면 확보·공항 세션 만료시간이 아님 |
| `request.browser_timeout_sec` | `30` | 공식 화면 응답 대기, 5~120초 |
| `storage.directory` | `"data/gimpo"` | 프로젝트 기준 SQLite·단일 실행 잠금 디렉터리 |

브라우저 세션과 환경변수에서 읽은 예약 비밀번호는 실행 중 메모리에서 사용하며 로그·SQLite·localStorage에 저장하지 않는다. 기본 정보는 이 PC에 자동 저장한다. T2의 차량번호·연락처도 명시적인 가져오기 버튼으로만 불러온다.

## 실행 범위와 복구

화면을 볼 수 있는 macOS/Linux PC의 단일 사용자·단일 프로세스를 지원한다. `python3 app.py`는 debug/reloader 없이 실행한다. 개발 reloader에서는 김포 작업을 거부한다. SQLite 경로의 OS 파일 잠금으로 두 번째 프로세스의 작업 시작을 막는다. 원격 서버·다중 WSGI worker·휴대전화로의 공식 세션 이전은 지원하지 않는다.

페이지를 새로고침하거나 자체 탭을 닫아도 공식 브라우저 작업은 유지된다. 재접속 시 기존 작업에 연결한다. 결제 확인창을 취소하거나 문서를 변경하면 기존 인계를 폐기하고 새 문서에서 다시 준비해야 한다. 인계 기한이 지나면 이전 문서에서 결제를 진행할 수 없다.

결제 준비 요청은 현재 입력·문서·금액·기한을 확인한 뒤 작업당 최초 한 번만 전달한다. 전송 가능성 기록 이후에는 중지·입력 수정·새 예약을 차단한다. 결과 불명인 경우 자동 재예약하지 않는다. 프로세스 재시작은 결제 전 작업을 중단 처리하고, 전송 가능성이 있는 작업은 활성 상태로 보존해 공식 결과 확인을 요구한다. 브라우저 세션·비밀번호를 복구하지 않는다. 애플리케이션의 요청 중복 차단이 서버의 정확히 한 번 처리나 중복 과금 방지를 보장하는 것은 아니다.

## 텔레그램 알림

T2와 김포는 공통 발송기·메시지 형식·재시도 정책을 사용한다. **`TELEGRAM_ALARM_ENABLED` 하나로 모든 공항의 알림을 켜고 끈다. 기본값은 `false`이며, 명시적으로 `true`로 설정해야 발송한다.** 대소문자는 구분하지 않으며, 빈 값이나 그 외의 값은 꺼짐으로 처리한다. 토큰이 있어도 이 값이 꺼져 있으면 테스트 알림을 포함해 전송하지 않는다. 알림을 꺼도 예약 조회·진행 기능은 동작한다.

| 환경변수 | 범위 | 기본값 / 의미 |
|---|---|---|
| `TELEGRAM_ALARM_ENABLED` | 공통 | `false`. `true`일 때만 텔레그램 발송 |
| `TELEGRAM_BOT_TOKEN` | 공통 | 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 공통 | 수신자 또는 채널 ID |

텔레그램 설정은 모두 접두사 없이 공통으로 관리한다. T2와 김포는 같은 봇과 수신자를 사용하며 서비스별 텔레그램 설정은 읽지 않는다.

BotFather에서 봇을 만든다. 개인 대화로 받으려면 사용자가 먼저 봇 대화를 시작한다. 채널로 받으려면 해당 채널에 봇을 관리자로 추가하고 **메시지 게시** 권한을 부여한다. Bot API에서 확인한 채팅·채널 ID를 그대로 사용하며 공개 채널은 `@채널사용자명`도 사용할 수 있다. 토큰과 수신자 ID는 커밋되는 TOML에 넣지 않는다.

프로젝트 루트의 `.env`에 다음 값을 등록한 뒤 `python3 app.py`로 실행한다.

```dotenv
TELEGRAM_ALARM_ENABLED=true
TELEGRAM_BOT_TOKEN='봇 토큰'
TELEGRAM_CHAT_ID='수신자 또는 채널 ID'
```

모든 공항의 알림을 끄려면 `TELEGRAM_ALARM_ENABLED=false`로 설정한다. 앱은 `.env`에서 위 세 가지 공통 설정을 읽으며, 실행 프로세스에 전달된 환경변수가 있으면 그 값을 우선한다(빈 값도 우선). `.env` 안의 변수 치환은 하지 않는다. 설정 변경은 앱 재시작 후 적용된다. `.env`가 없거나 읽을 수 없으면 환경변수와 기본값을 사용한다.

공통 전송 정책은 `config/notifications.toml`의 `telegram.max_attempts`에서 관리한다(기본 3, 허용 1~3). 공용 TOML 로더로 엄격하게 검증한다. 명확한 일시 서버 오류·429에만 제한 재시도하며, 타임아웃은 `UNKNOWN`으로 멈추고 자동 재전송하지 않는다. 알림 실패 때문에 예약 API나 브라우저 절차를 다시 실행하지 않는다. `DISABLED`는 공통 알림 꺼짐, `FAILED`는 설정 오류 또는 발송 실패를 뜻한다.

상단 **설정** 메뉴(`/settings/`)에서 공통 알림 설정과 서비스별 전송 상태·테스트 결과를 확인한다. 환경변수 값은 표시하지 않는다. 알림이 꺼져 있어도 공통 봇·수신자 설정 여부는 확인할 수 있다. 화면에서는 설정을 변경하지 않으며, `.env` 또는 환경변수를 변경한 뒤 앱을 재시작해야 한다.

각 서비스의 **테스트 알림**은 알림이 켜져 있고 봇 토큰과 수신자 ID가 모두 설정됐을 때 사용할 수 있다. 설정 화면 조회만으로는 예약 작업·브라우저·알림 전송을 시작하지 않는다. 테스트 알림도 예약 작업과 별도로 처리한다. 예약 화면의 설정 링크는 입력 내용을 유지하도록 새 탭으로 열린다. 김포 예약별 알림 결과와 **알림 다시 보내기**는 해당 예약 화면에 남아 있다.

상태 조회는 `GET /t2-valet/api/notifications/status`, `GET /gimpo-parking/api/notifications/status`, 테스트 전송은 각 경로의 `/status`를 `/test`로 바꾼 주소에 JSON `{}`를 POST한다.

### 메시지 형식

모든 알림은 `[공항·서비스] 결과` → 예약 요약 → 사용자가 할 일 → 작업번호 순서의 일반 텍스트다. 날짜·시간은 서울 기준이며, 이름·차량번호·전화번호·예약 비밀번호·쿠키·PG 토큰·봇 토큰·원본 API 응답은 포함하지 않는다.

T2는 **HTTP 200 예약 성공 판정**에 연결한다. 자동 예약과 1회 예약 요청 모두 성공하면 알리며, 알림은 별도 큐로 보내 예약 요청을 늦추거나 다시 실행하지 않는다. 검증되지 않은 예약번호는 만들지 않는다.

```text
[인천공항 T2 발렛] 예약 완료

입차: 2026-10-03 11:00
출차: 2026-10-06 18:00
확인 시각: 2026-10-01 09:24:00 (서울)

공항 사이트에서 예약 내역을 확인해주세요.

작업: ICN-T2-작업번호
```

김포는 `[김포공항 국내선 주차] 결제 대기 — 예약 미완료` 제목 아래 주차장·입출차·공식 요금·보증금·최종 조회 시각을 표시하고, 실행 중인 PC에서 직접 결제하도록 안내한다. 취소·만료·실행 종료 등으로 안내가 무효화되면 `[김포공항 국내선 주차] 결제 안내 변경`을 보낸다. 아직 지원하지 않는 실제 예약 완료를 자동 판정하지 않는다.

**알림 다시 보내기**는 김포의 현재 유효한 안내만 다시 보내며, 중복 도착할 수 있다. T2의 단순 완료 알림 큐는 메모리 기반이라 프로세스 종료 후 미전송 알림을 복구하지 않는다. 김포 인계 알림은 SQLite outbox의 복구 규칙을 따른다.

공식 참고: [Telegram sendMessage](https://core.telegram.org/bots/api#sendmessage), [응답의 retry_after](https://core.telegram.org/bots/api#responseparameters).

## 보안

- 이 PC의 브라우저에서만 쓰는 로컬 서비스다. Host가 `localhost`·`127.0.0.1`이 아닌 요청은 400, 다른 사이트에서 보낸 POST는 403으로 거절한다. 다른 기기에서 접속하게 하려면 인증부터 붙여야 한다.
- `user_data.json`과 `logs/api_call.log`는 소유자만 읽고 쓴다(0600). 이전 버전이 만든 파일도 읽거나 쓸 때 권한을 좁힌다. 다른 사용자 소유 파일(`sudo`로 실행해 생긴 파일 등)은 권한을 바꾸지 않고 연다.
- 로그와 화면에는 예약자명·휴대전화 번호·차량번호를 가려서 남긴다. 예약 API에는 원본을 보낸다. 이전 버전이 남긴 로그는 가려져 있지 않으니 화면의 로그 초기화로 지운다. 화면에는 최근 500건을 보이고, 로그 파일이 1,000,000바이트를 넘으면 최근 500건만 남긴다.
- T2 화면은 CSP로 같은 출처의 스크립트만 실행한다. 버튼 동작은 인라인 `onclick` 대신 `static/js/app.js`에서 연결한다.
- 의존성 취약점 점검: `pip install pip-audit && pip-audit -r requirements.txt`

## 구조

`GimpoService`는 구성과 지연 시작, `GimpoRuntime`은 명령·브라우저 수명, `JobStore`는 SQLite 트랜잭션을 담당한다. `BrowserClient`·`Notifier` 인터페이스를 주입하므로 공식 브라우저와 텔레그램을 테스트 대역으로 바꿀 수 있다. `PlaywrightGimpoClient`는 공식 화면 어댑터, `NotificationOutbox`는 김포 상태 변경과 연결된 알림 전달을 담당한다. `TelegramNotifier`, `DeliveryPolicy`, `ReservationMessages`는 공통 기능이며 T2는 `BackgroundNotifications`로 비동기 발송한다. 상태마다 상속 클래스를 만들거나 패턴 수를 맞추지 않고 책임 분리·어댑터·팩터리 주입·저장소와 트랜잭션을 필요한 곳에 적용한다.

| 위치 | 맡는 일 |
|---|---|
| `services/config.py` | 서비스 공용 TOML 설정 로더 |
| `services/web_security.py` | 앱 전체 Host 제한, 다른 출처 POST 거부, 공통 보안 헤더 |
| `services/t2/` | T2 라우트·예약 API 호출(`valet`), 입력 검사(`validation`), 파일 저장(`storage`), 반복 호출 워커(`scheduler`) |
| `services/gimpo/` | 김포 라우트·서비스(`parking`), 작업 실행(`jobs`), 공식 화면 어댑터(`client`), SQLite 저장소(`store`), 입력 검사(`validation`), 설정(`config`) |
| `services/notifications/` | 텔레그램 발송(`telegram`), 설정(`config`), 메시지 형식(`messages`), T2 비동기 큐(`background`), 김포 outbox(`outbox`) |

## 테스트

```bash
python3 -m playwright install chromium
python3 -m pytest -q
```

Python HTTP 호출은 기본 차단한다. 브라우저 통합 테스트도 공식 도메인의 모든 응답을 로컬 fixture로 제공하고 그 외 통신을 차단한다. 테스트 중 실예약·결제·텔레그램 전송은 없다.
